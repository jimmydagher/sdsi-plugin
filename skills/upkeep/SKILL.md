# SDSI: Upkeep

Before anything else, read `../core/SKILL.md` and run its steps.

A skill only loads when it's invoked or its triggers match, so a rule like "update the design documents before code" lapses the moment the skill that owns it isn't running. Upkeep closes that gap: each topic's `## Upkeep` section lists its standing instructions as one-line triggers — *when X → do Y (`sdsi:<topic>`)* — and this skill installs them in the project, in a file Claude Code loads at the start of every session.

**This skill holds no rules of its own.** The instructions live only in the topics' `## Upkeep` sections; this skill copies them. To change an instruction, edit its topic, then refresh projects.

## The file

`.claude/rules/sdsi.md` — Claude Code loads every Markdown file in `.claude/rules/` without a `paths:` frontmatter at session start, alongside `CLAUDE.md`. The project's own `CLAUDE.md` is never edited, apart from the profile's `Upkeep` field (below).

```markdown
# SDSI upkeep

Standing instructions from the `sdsi` plugin (x.y.z). Generated by `sdsi:upkeep` — to change one, edit the topic skill and run `/sdsi:upkeep` again; to drop one, run `/sdsi:upkeep` and remove its topic.

## sdsi:workflow

- Before code for a new feature or a change in behavior … (`sdsi:workflow`)

## sdsi:docs

- Any change that affects a document … (`sdsi:docs`)
```

- **One `## sdsi:<topic>` section per installed topic**, holding that topic's Upkeep lines word for word, in core §4's order.
- **The plugin version** it was generated from goes in the intro (`../../.claude-plugin/plugin.json`), so a review can tell when it's stale.
- **The profile records the choice** — `.claude/CLAUDE.md`'s `## SDSI profile` gets `- Upkeep: workflow, docs, versioning, testing`, or `- Upkeep: declined` when the human said no, so no later session asks again (core §1 Step 5).

## Apply

1. **Which topics** — the ones passed in (by a calling skill or the arguments); otherwise ask with `AskUserQuestion` (multi-select): every topic with an `## Upkeep` section, the installed ones marked. A topic dropped from the selection is removed from the file.
2. **Write the file** from each chosen topic's current `## Upkeep` section — the whole file regenerated, never patched line by line, so it can't drift from the skills.
3. **Update the profile's `Upkeep` field.** Removing every topic deletes the file and records `declined`.
4. **Report** which topics were installed, refreshed, or removed, and quote the file.

**Refreshing after a plugin upgrade** is the same run with the installed topics: the file is regenerated from the topics' current text.

## Review checklist

A project with an `Upkeep` profile field but no `.claude/rules/sdsi.md`, or the reverse · a topic section whose lines differ from that topic's current `## Upkeep` (stale — refresh) · a file generated by an older plugin version · a hand edit to the generated file (move the project's own rule into `CLAUDE.md`, then regenerate) · an upkeep instruction copied into `CLAUDE.md` instead of installed here · a `paths:` frontmatter on the file, which stops it loading every session.
